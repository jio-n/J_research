# 原文から定義を置き、展示で確かめる

2026年10月22日／視察前の調査基準案。メーカーによる名付け、今回の調査で重視する能力、技術の新規性は別々に記録する。唯一の一般定義を決めた資料ではない。

## 1. 何をフィジカルAIと呼んでいるか

| 原文集の根拠 | その資料が説明すること | 今回の確認で重視する点 |
|---|---|---|
| [Q07・ファナック安部氏](01_verbatim_evidence.md#q07)、[Q09・ファナック公式](01_verbatim_evidence.md#q09) | 環境の認識、AIによる演算、動作の判断と実行 | AIがどの入力から、何の動作を選ぶのか |
| [Q21・KPMGの解説](01_verbatim_evidence.md#q21) | 観測した変化に応じた行動の選び直し | 変化の種類と、実際に変えられる判断・動作 |
| [Q41・NVIDIA公式教材](01_verbatim_evidence.md#q41) | 知覚・理解・実行と、現実環境の不確実性への適応 | 決められた条件を外れたときの対応範囲 |
| [Q02・DMG森精機](01_verbatim_evidence.md#q02)、[Q31・三菱電機](01_verbatim_evidence.md#q31) | 設備データと製造向けAI、物理モデルと制御への応用 | ロボットだけに限定せず、加工・設備の判断と実行も調べる |

これらを根拠に、今回の重点対象を次のように置く。

**センサ等で物理世界の状態を捉え、学習モデルを含むAIが状態・目的に応じて判断や動作を選び、その結果を物理世界で実行する仕組み。そのうち、条件の変化や不確実性への対応能力を具体的に確認できるものを重点的に紹介する。**

これは資料を組み合わせた本調査の作業定義。ファナックの発言そのものでも、各社が合意した規格でもない。「広い意味ではAIを用いた物理動作」と「今回注目する適応能力」を区別することで、企業の呼称を尊重しながら、報告の基準を明示できる。

未知条件への汎化、VLA、基盤モデル、世界モデル、模倣学習、強化学習、接触を含む方策などは調べる技術項目であり、全てを必須条件にはしない。実行時に動作を変えることと、モデル自体をその場で再学習することも別である。毎回のオンライン学習を条件にしない。

## 2. 「据え付けのピッキング」をどう扱うか

以下は判定方法を説明する仮想例であり、実際に確認したJIMTOF展示ではない。

| 例 | いったんの整理 | 追加で確かめること |
|---|---|---|
| 同じワークを撮像し、位置を補正して登録済みの経路で運ぶ | 従来型の自動化としても成立する。画像認識にAIを使っているかは別途確認 | 認識方式、経路生成方式、以前の製品との差。名称だけで新しい適応能力を認めない |
| 固定アームが同じ種類のワークを扱うが、姿勢・遮蔽・滑りに応じて把持や再試行を変える | 固定設置・同種ワークでも重点対象の候補になる | 学習した部分、実際に変えられる動作、失敗検知、復帰、試験条件と成功率 |
| 音声で指示できるが、実行は登録済みの作業メニューだけ | 指示入力の改善は確認できる。新しい動作への適応は未確認 | 言い換え理解と新規作業生成を区別し、作業範囲を聞く |
| 初めての形状や新しい指示に、再教示を抑えて対応すると説明する | 汎化を主張する候補 | 「初めて」の範囲、学習データとの関係、再教示時間、人の介入、比較試験 |
| 加工中の信号から状態を推定し、モデルに基づいて条件を変更する | ロボットでなくても、加工における適応的な判断・実行として調べる | 何を推定し何を変えるか、物理モデルと学習の分担、安定性、適用範囲 |

AIを使った旧来の画像認識も広い定義に入る場合がある。「フィジカルAIか」と「2024年以前に比べて何が新しくなったか」を一問で済ませない。展示の見た目だけで方式や汎化を推定しない。

## 3. タスクの名前で比較する

AI・エージェント・デジタルツインは手段の軸に置く。企業と製品は、まず顧客が任せたい仕事に置く。分類は複数選択でよく、工程と技術を1対1に無理に割り当てない。

| ID | 顧客の仕事 | 入力→出力／比較する能力 |
|---|---|---|
| T01 | 工程設計 | 図面・要求・設備制約→工程順序、加工法、段取り案 |
| T02 | NCプログラム・工具経路作成 | 形状・工具・工程→パス、NC、干渉の確認 |
| T03 | 加工条件・工具選定 | 材料・要求品質・設備条件→工具、速度・送り等の条件 |
| T04 | 生産計画・再計画 | 受注・負荷・稼働状況→割付、順序、遅延時の組み直し |
| T05 | 段取り・ワーク保持・交換 | 対象・設備・治具→保持方法、交換、教示・調整 |
| T06 | ピッキング・供給・搬送 | 位置・姿勢・周囲の状態→把持、供給、搬送経路 |
| T07 | 加工中の補正・制御 | 加工中の信号・状態推定→条件や動作の補正 |
| T08 | 組立・研磨・バリ取り等の作業動作 | 形状・接触・目的→作業手順と力・動作の調整 |
| T09 | 計測・検査・品質判定 | 測定・画像・仕様→合否、偏差、次の対応 |
| T10 | 原因分析・改善策立案 | 不良・設備・材料・作業履歴→原因候補と検証案 |
| T11 | 保全・復旧支援 | 診断・履歴・部品情報→異常判断、保全、復旧手順 |
| T12 | データ取得・モデル化・学習検証〔横断基盤〕 | 現象・目的→取得仕様、整備データ、モデル、適用範囲の検証 |
| T13 | 技能・判断の記録と再利用〔横断基盤〕 | 判断の前提・理由・代替案・結果→次の業務で使える知識 |
| T14 | 工程・工場全体の最適化〔工程間の連携〕 | 各工程の制約・品質・進捗→工程をまたぐ調整と実行への反映 |

「自律加工」はT01～T03・T05・T07・T09等を含み得る総称なので、個別の資料では**自動化した判断範囲**を付記する。加工中の補正だけを、工程設計から品質保証まで全て自律化した証拠にしない。機械可読の定義は [task_taxonomy.json](task_taxonomy.json)。既存344技術の全面再分類は次の作業であり、この原文集のタグだけで完了したとはしない。

## 4. 訪問時に埋める評価票

| 記録項目 | 聞き方・残す根拠 |
|---|---|
| 呼称 | 企業がPhysical AI等と明記しているか。原文・出典・発言者を記録 |
| タスクと製品 | T01～T14、製品名、対象ユーザー、前後工程 |
| 状態の入力 | カメラ、力覚、電流、振動、CNC情報、計画・品質等のうち何を使うか |
| AIが決めること | 認識だけか、条件選定・計画・経路・動作・再試行までか |
| 対応する変化 | 位置・姿勢、材質・形状、接触、工具摩耗、異常、作業指示、工程遅延等 |
| 技術の仕組み | 学習モデルとルール・数値計算・物理モデル・既存制御の分担。未開示なら未開示 |
| 学習と適応の範囲 | 事前の対象／新規対象、学習・再教示の必要量、その場の動作変更／モデル更新 |
| 人の役割 | 情報提示、人の承認後に実行、条件内で自動実行、例外時の復帰。対象範囲を記す |
| 根拠の強さ | 説明だけ、公式の技術資料、比較条件を示す実機検証、現地観察。条件・試行数・成功率・介入率・時間 |
| 実用段階 | 開発計画、研究実証、商品化、展示予定、現地確認。利用開始条件と適用制約 |
| 新規性 | 2024年または従来方式との比較。機能、適用範囲、調整工数、性能のどれが変わったか |
| つなぐ相手 | 入出力API、データの意味、設備間の制約、責任範囲、閉ループで戻せる先 |
| 顧客価値 | 何の作業・損失を減らすか、保守・契約、利用データの権利、横展開の追加工数 |

空欄は「未確認」とする。確認できない技術を推測で埋めない。[記入用JSON](exhibit_assessment_template.json) を複製して使える。

報告では、①メーカーがそう呼ぶ、②AIの方式と変化への対応を資料で確認、③条件を示した実機検証を確認、④現地で確認、を独立した欄にする。足し合わせて総合点にせず、例えば「メーカー呼称あり／適応能力は資料記載／実演の比較条件は未確認」と書く。現地の一回の成功も、未知条件全般への汎化の証明にはしない。

## 5. 潮流・各社・開発候補を結ぶ報告の形

原文の抜粋→その文が支える方向性→顧客タスク→技術の入出力と実証範囲→不足している能力→開発候補、の順に根拠をつなぐ。次の表は既存資料からの**仮説と追加確認点**であり、実地確認後の結論ではない。

| 方向性と根拠 | 見るタスク・企業例 | 顧客向け開発を考える問い |
|---|---|---|
| データ取得を現象理解と結ぶ：Q01・Q03・Q39 | T12、産総研・DMG森精機／WALC | 取得点・同期・取得条件・品質との対応を設計し、学習と物理モデル検証の両方に使えるか |
| 技能を単なる手順以上の知識にする：Q05・Q13・Q14・Q46 | T01～T03・T10・T13、マザック／ABEJA、Hexagon、東芝 | 目的、制約、選択理由、計算への入力と結果まで記録し、別案件での条件決定に再利用できるか |
| 物理モデルと実測の役割を分ける：Q24・Q31・Q40・Q44 | T03・T07・T11・T12、DMG森精機、三菱電機、Third Wave Systems | モデルの同定・校正、少量実測、適用範囲の検証を顧客に提供する余地があるか |
| 計画と現場の判断をつなぐ：Q10・Q11・Q42・Q45 | T04・T14、NEC、Siemens、富士通、コマツ／産総研 | 計画変更を現場へ渡し、実績・異常を再計画へ返す接点はどこか。局所の改善が全体の悪化を生まないか |
| 現場での適応と共同開発：Q06～Q09 | T06・T08・T12、ファナック／日立 | データ取得と実証を進める連携が、どの変化への対応能力に結び付くのか |
| 継続利用と改善の循環：Q02・Q25～Q29・Q36・Q43 | T11・T12・T13、DMG森精機／テクニウム、Beckhoff | 診断・提案の品質、顧客効果、継続契約、提供原価を別々に検証できるか。AI精度から利益への直結はまだ仮説 |

「穴がある」と結論する前に、既存ベンダーの提供範囲、顧客の未充足需要、データ利用条件、導入・保守コストを調べる。自社の技術・販売経路は未確認なので、参入可能性は条件付きで示す。
